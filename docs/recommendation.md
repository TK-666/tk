# 推荐模块设计

## 输入与行为权重

只对 `published` 作品计算推荐。用户明确设置的风格标签构成初始偏好；浏览、当前点赞、当前收藏和评分构成行为历史。每个用户对每件作品的正向强度为：

```text
w(u, i) = 0.2 × min(浏览次数, 3)
        + 2 × 当前已点赞
        + 3 × 当前已收藏
        + max(评分 − 3, 0)
```

评分为 1 或 2 的作品从该用户的个人推荐中排除。点赞、收藏以当前状态为准，避免取消操作留下的日志继续增加推荐分数；浏览次数最多计 3 次，避免刷新页面反复放大同一行为。停用账号不参与统计。

## 物品协同过滤

将用户与作品的正向强度作为行为矩阵。先把每个强度截断到 5；对同一用户互动过的作品两两累计共现，再用物品向量的长度归一化：

```text
co(i, j) = Σu [min(w(u,i),5) × min(w(u,j),5) / log2(用户u的正向作品数+1)]
sim(i, j) = co(i,j) / sqrt(Σu min(w(u,i),5)² × Σu min(w(u,j),5)²)
```

只为存在共同正向用户的作品计算相似度。目标用户的 ItemCF 得分为其历史作品强度与候选作品相似度的加权和。活跃用户的共现贡献经过对数折减，减少单个用户大量浏览对结果的影响。

## 混合排序与冷启动

明确选择的风格标签初始亲和度为 1；历史作品的标签按行为强度累加，风格标签系数为 0.6，题材、媒介和年代标签系数为 0.2。个人推荐分数为：

```text
标签权重 × 候选作品的标签亲和度之和
+ ItemCF权重 × 用户历史作品与候选作品的相似度加权和
+ 0.2 × ln(1 + 热门分数)
+ 2（管理员置顶时）
```

标签与 ItemCF 权重由管理员配置。已互动作品排在未互动作品之后，在候选不足时仍可补充；明确低评分的作品不进入个人推荐。仅设置风格偏好时按标签推荐；没有偏好或正向历史时回退到热门作品；访客也使用热门回退。接口以 `strategy` 标识所用路径，并为每件作品返回 `recommendation_reason`。

热门作品按管理员置顶、当前有效行为的热门分数、上传时间排序。热门分数中每个用户对一件作品最多贡献 3 次浏览，并按当前点赞、收藏和高评分加权。最新作品按上传时间排序。`/api/recommendations` 支持 `kind=personal|hot|latest` 和 `limit=1..50`。

## 运行边界与验证

当前实现每次请求从数据库计算行为矩阵和相似度，适合毕业设计演示规模。作品和用户量增大后，应预计算相似度、缓存热门榜，并评估 Precision@K、Recall@K、NDCG@K 及接口延迟。`backend/tests/test_recommendation.py` 覆盖访客、偏好、浏览、ItemCF、撤销收藏、低评分、上下架和参数范围；合并前仍需以真实作品数据观察推荐质量。
