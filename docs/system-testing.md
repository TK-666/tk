## 已修复的问题

1. 注册和修改密码时，非字符串值原先会被转换成文本并保存；昵称和标签名也有相同问题。现在拒绝这些输入，原有有效数据不变。
2. 标签编号原先会把布尔值和小数转换为整数，可能选中错误标签。现在只接受整数或整数文本。
3. 同一用户同时收藏同一作品时，修复前 25 个请求中有 4 个返回 409；并发取消在 MySQL 下还可能返回过期状态。现在并发重复请求返回当前状态，并且只记录一次实际的收藏或取消操作。

这些问题的回归用例位于 [`backend/tests/test_system_validation.py`](../backend/tests/test_system_validation.py)、[`backend/tests/test_mysql.py`](../backend/tests/test_mysql.py) 和下述压测脚本。

## 本地 HTTP 压测

压测使用 [`scripts/system_load_test.py`](../scripts/system_load_test.py)：每次新建并清理独立 SQLite 数据库，使用 46 件作品元数据、50 个合成用户、500 次浏览、150 条收藏、150 条点赞和 50 条评分。图片接口重复读取一张约 300 KB 的样本图。客户端与 Werkzeug 多线程开发服务器位于同一台电脑，使用本地 HTTP；每个接口在每种并发下各发送 60 个请求，各接口分开测试。正式运行时间为 2026-11-07 22:03（香港时间），原始数据见 [`system-test-results.json`](system-test-results.json)。

| 接口 | 1 并发 P95 | 10 并发 P95 | 25 并发 P95 | 25 并发吞吐量 |
| --- | ---: | ---: | ---: | ---: |
| 作品列表 | 27.62 ms | 41.60 ms | 122.23 ms | 246.12 次/秒 |
| 关键词搜索 | 27.29 ms | 34.13 ms | 112.69 ms | 267.27 次/秒 |
| 热门推荐 | 27.66 ms | 196.39 ms | 545.78 ms | 54.66 次/秒 |
| 个性化推荐 | 27.79 ms | 224.26 ms | 676.38 ms | 44.59 次/秒 |
| 图片读取 | 19.71 ms | 29.63 ms | 63.53 ms | 445.59 次/秒 |

900 次只读请求全部成功。随后各发送 25 个同时收藏及取消收藏请求，50 次均返回 200；数据库分别只有一条收藏事件和一条取消事件，最终无收藏记录。P95 使用最近秩法计算，仅统计成功请求；吞吐量为该批次请求数除以批次总耗时。每组只有 60 个样本，数值适合作为本机演示规模的参考，不是生产容量或长期稳定性结论。

推荐请求的 P95 在 25 并发下升高，原因需要进一步剖析；当前实现每次请求重新读取行为并计算相似度。扩大数据量或上线前，应在目标服务器和 MySQL 上进行更长时间的混合读写压测，再评估预计算或缓存，并验证结果更新和失效规则。任务书未给出具体性能阈值，本次不据此声称达到某个生产性能标准。

## 复现

在 `backend` 目录运行 `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`。MySQL 实库测试需要通过环境变量提供 `MYSQL_TEST_PASSWORD`，并允许创建和删除测试脚本生成的临时库。项目根目录运行：

```powershell
.\backend\.venv\Scripts\python.exe .\scripts\system_load_test.py --requests 60 --output docs\system-test-results.json
```

该脚本只绑定本机临时端口，不连接项目现有数据库。结果会因机器负载、版本和环境变化而不同。
